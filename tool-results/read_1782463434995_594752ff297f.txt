    21→🏗️ SECTION 1: SYSTEM PHILOSOPHY & DESIGN PRINCIPLES
    22→
    23→Before writing a single line of code, internalize these non-negotiable principles:
    24→
    25→1.1 Zero-Latency UX Doctrine
    26→Every user interaction — from a front-desk login to a housekeeping status update — must respond in under 200ms on a standard broadband connection. Design all API endpoints, database queries, and state management with this constraint as a hard ceiling.
    27→
    28→1.2 Offline-First Architecture
    29→A hotel at 3:00 AM cannot depend on a cloud server being up. Critical operations — check-in, check-out, room status updates, POS billing — must function in offline mode using IndexedDB or SQLite local storage and sync when connectivity restores. Implement Conflict-Free Replicated Data Types (CRDTs) for sync resolution.
    30→
    31→1.3 Role-Integrity Principle
    32→Every screen, every button, every API call must be rendered and authorized based on Role + Property + Shift context. A manager at Property A must be invisible to Property B. A night-shift employee must not see day-shift payroll data. This is not just middleware — it is the DNA of every component.
    33→
    34→1.4 Audit-First Design
    35→Every state change in the system — price override, room reassignment, discount applied, complaint escalated — must generate an immutable audit log entry with: Actor ID, Role, Timestamp (UTC + local), Previous Value, New Value, IP Address, Device Fingerprint, and Session Token. This is non-negotiable for compliance (GDPR, PCI-DSS, ISO 27001).
    36→
    37→1.5 Revenue Intelligence by Default
    38→This system must not merely record transactions. It must predict, optimize, and alert. Every dashboard at every role level must surface actionable revenue intelligence — not vanity metrics.

   990→📊 SECTION 6: ANALYTICS ENGINE SPECIFICATION
   991→
   992→6.1 Key Performance Indicators (KPIs) — Defined
   993→
   994→Every KPI displayed must be calculated correctly. Never approximate.
   995→
   996→Occupancy Rate = (Occupied Rooms / Available Rooms) × 100
   997→Available Rooms = Total Rooms - Out of Order Rooms
   998→
   999→ADR (Average Daily Rate) = Total Room Revenue / Total Rooms Sold
  1000→Rooms Sold = Occupied rooms. Complimentary rooms excluded from revenue but included in occupancy.
  1001→
  1002→RevPAR (Revenue Per Available Room) = ADR × Occupancy Rate
  1003→OR RevPAR = Total Room Revenue / Available Rooms
  1004→Both formulas yield the same result — verify in code.
  1005→
  1006→TRevPAR (Total Revenue Per Available Room) = Total Property Revenue / Available Rooms
  1007→Includes F&B, SPA, Laundry, Other — not just rooms
  1008→
  1009→GOPPAR (Gross Operating Profit Per Available Room) = Gross Operating Profit / Available Rooms
  1010→
  1011→NPS (Net Promoter Score) = % Promoters (9-10) - % Detractors (0-6)
  1012→
  1013→CPOR (Cost Per Occupied Room) = Total Operating Expenses / Occupied Rooms
  1014→
  1015→Channel Contribution % = Revenue from Channel / Total Revenue × 100

  1059→🔒 SECTION 7: SECURITY ARCHITECTURE
  1060→
  1061→7.1 Application Security
  1062→
  1063→OWASP Top 10 mitigation — every item addressed:
  1064→
  1065→
  1066→Injection: Prisma ORM parameterized queries. Zero raw SQL with user input.
  1067→Broken Auth: JWT RS256 + Refresh token rotation + session blacklist in Redis.
  1068→Sensitive Data Exposure: AES-256 for guest PII at rest. TLS 1.3 in transit. PAN tokenization for payment data.
  1069→XML/XXE: Not applicable (JSON API). Validate all external XML (OTA channel feeds).
  1070→Broken Access Control: Row-Level Security in PostgreSQL. API middleware validates role + property ownership on every request.
  1071→Security Misconfiguration: Helm charts + Terraform with security groups. No default credentials. Secrets in AWS Secrets Manager only.
  1072→XSS: Content Security Policy headers. React JSX escapes by default. Sanitize all rich text inputs with DOMPurify.
  1073→Insecure Deserialization: Zod schema validation on all incoming payloads. No eval() or JSON.parse on untrusted data.
  1074→Vulnerable Dependencies: Snyk + Dependabot automated scanning. Weekly dependency audit in CI.
  1075→Insufficient Logging: Every API request logged with RequestID. Audit log for all state changes (see Section 4.9).
  1076→
  1077→
  1078→Additional Controls:
  1079→
  1080→
  1081→Rate limiting: 100 req/min per IP on public endpoints, 1000 req/min per authenticated user (Redis-backed via express-rate-limit)
  1082→CORS: Whitelist only known frontend domains
  1083→Helmet.js: Set all security headers (HSTS, X-Frame-Options, CSP, etc.)
  1084→SQL injection: Prisma prevents by design. Additional: pg-escape for any raw queries
  1085→File uploads: Type validation, size limit (10MB), virus scan via ClamAV before storage
  1086→PCI-DSS compliance: Never store raw card numbers. Use Razorpay/Stripe tokenization.

  1245→Night Audit runs at property's configured rollover time (default: 11:59 PM local time). This is the most critical automated process.

  1247→Night Audit Steps (automated, sequential, atomic transaction):
  1248→
  1249→
  1250→Post room charges to all in-house folios (room rate × nights)
  1251→Post meal plan charges (if MAP/AP package)
  1252→Advance reservations arriving tomorrow from tentative to confirmed
  1253→Mark no-shows (reservations with check-in date = today, status = confirmed, not checked in)
  1254→Apply cancellation charges for no-shows per policy
  1255→Roll business date to next day
  1256→Generate Night Audit report
  1257→Email report to GM and Owner
  1258→Backup snapshot of all financial data to audit-safe storage
  1259→
  1260→
  1261→If any step fails: Rollback entire transaction. Alert GM via push notification. Log failure with full context.
