    21→    21→🏗️ SECTION 1: SYSTEM PHILOSOPHY & DESIGN PRINCIPLES
    22→    22→
    23→    23→Before writing a single line of code, internalize these non-negotiable principles:
    24→    24→
    25→    25→1.1 Zero-Latency UX Doctrine
    26→    26→Every user interaction — from a front-desk login to a housekeeping status update — must respond in under 200ms on a standard broadband connection. Design all API endpoints, database queries, and state management with this constraint as a hard ceiling.
    27→    27→
    28→    28→1.2 Offline-First Architecture
    29→    29→A hotel at 3:00 AM cannot depend on a cloud server being up. Critical operations — check-in, check-out, room status updates, POS billing — must function in offline mode using IndexedDB or SQLite local storage and sync when connectivity restores. Implement Conflict-Free Replicated Data Types (CRDTs) for sync resolution.
    30→    30→
    31→    31→1.3 Role-Integrity Principle
    32→    32→Every screen, every button, every API call must be rendered and authorized based on Role + Property + Shift context. A manager at Property A must be invisible to Property B. A night-shift employee must not see day-shift payroll data. This is not just middleware — it is the DNA of every component.
    33→    33→
    34→    34→1.4 Audit-First Design
    35→    35→Every state change in the system — price override, room reassignment, discount applied, complaint escalated — must generate an immutable audit log entry with: Actor ID, Role, Timestamp (UTC + local), Previous Value, New Value, IP Address, Device Fingerprint, and Session Token. This is non-negotiable for compliance (GDPR, PCI-DSS, ISO 27001).
    36→    36→
    37→    37→1.5 Revenue Intelligence by Default
    38→    38→This system must not merely record transactions. It must predict, optimize, and alert. Every dashboard at every role level must surface actionable revenue intelligence — not vanity metrics.

   990→   990→📊 SECTION 6: ANALYTICS ENGINE SPECIFICATION
   991→   991→
   992→   992→6.1 Key Performance Indicators (KPIs) — Defined
   993→   993→
   994→   994→Every KPI displayed must be calculated correctly. Never approximate.
   995→   995→
   996→   996→Occupancy Rate = (Occupied Rooms / Available Rooms) × 100
   997→   997→Available Rooms = Total Rooms - Out of Order Rooms
   998→   998→
   999→   999→ADR (Average Daily Rate) = Total Room Revenue / Total Rooms Sold
  1000→  1000→Rooms Sold = Occupied rooms. Complimentary rooms excluded from revenue but included in occupancy.
  1001→  1001→
  1002→  1002→RevPAR (Revenue Per Available Room) = ADR × Occupancy Rate
  1003→  1003→OR RevPAR = Total Room Revenue / Available Rooms
  1004→  1004→Both formulas yield the same result — verify in code.
  1005→  1005→
  1006→  1006→TRevPAR (Total Revenue Per Available Room) = Total Property Revenue / Available Rooms
  1007→  1007→Includes F&B, SPA, Laundry, Other — not just rooms
  1008→  1008→
  1009→  1009→GOPPAR (Gross Operating Profit Per Available Room) = Gross Operating Profit / Available Rooms
  1010→  1010→
  1011→  1011→NPS (Net Promoter Score) = % Promoters (9-10) - % Detractors (0-6)
  1012→  1012→
  1013→  1013→CPOR (Cost Per Occupied Room) = Total Operating Expenses / Occupied Rooms
  1014→  1014→
  1015→  1015→Channel Contribution % = Revenue from Channel / Total Revenue × 100

  1060→  1060→
  1061→  1061→7.1 Application Security
  1062→  1062→
  1063→  1063→OWASP Top 10 mitigation — every item addressed:
  1064→  1064→
  1065→  1065→
  1066→  1066→Injection: Prisma ORM parameterized queries. Zero raw SQL with user input.
  1067→  1067→Broken Auth: JWT RS256 + Refresh token rotation + session blacklist in Redis.
  1068→  1068→Sensitive Data Exposure: AES-256 for guest PII at rest. TLS 1.3 in transit. PAN tokenization for payment data.
  1069→  1069→XML/XXE: Not applicable (JSON API). Validate all external XML (OTA channel feeds).
  1070→  1070→Broken Access Control: Row-Level Security in PostgreSQL. API middleware validates role + property ownership on every request.
  1071→  1071→Security Misconfiguration: Helm charts + Terraform with security groups. No default credentials. Secrets in AWS Secrets Manager only.
  1072→  1072→XSS: Content Security Policy headers. React JSX escapes by default. Sanitize all rich text inputs with DOMPurify.
  1073→  1073→Insecure Deserialization: Zod schema validation on all incoming payloads. No eval() or JSON.parse on untrusted data.
  1074→  1074→Vulnerable Dependencies: Snyk + Dependabot automated scanning. Weekly dependency audit in CI.
  1075→  1075→Insufficient Logging: Every API request logged with RequestID. Audit log for all state changes (see Section 4.9).
  1076→  1076→
  1077→  1077→
  1078→  1078→Additional Controls:
  1079→  1079→
  1080→  1080→
  1081→  1081→Rate limiting: 100 req/min per IP on public endpoints, 1000 req/min per authenticated user (Redis-backed via express-rate-limit)
  1082→  1082→CORS: Whitelist only known frontend domains
  1083→  1083→Helmet.js: Set all security headers (HSTS, X-Frame-Options, CSP, etc.)
  1084→  1084→SQL injection: Prisma prevents by design. Additional: pg-escape for any raw queries
  1085→  1085→File uploads: Type validation, size limit (10MB), virus scan via ClamAV before storage
  1086→  1086→PCI-DSS compliance: Never store raw card numbers. Use Razorpay/Stripe tokenization.
