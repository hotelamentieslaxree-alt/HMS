🏗️ SECTION 1: SYSTEM PHILOSOPHY & DESIGN PRINCIPLES

Before writing a single line of code, internalize these non-negotiable principles:

1.1 Zero-Latency UX Doctrine
Every user interaction — from a front-desk login to a housekeeping status update — must respond in under 200ms on a standard broadband connection. Design all API endpoints, database queries, and state management with this constraint as a hard ceiling.

1.2 Offline-First Architecture
A hotel at 3:00 AM cannot depend on a cloud server being up. Critical operations — check-in, check-out, room status updates, POS billing — must function in offline mode using IndexedDB or SQLite local storage and sync when connectivity restores. Implement Conflict-Free Replicated Data Types (CRDTs) for sync resolution.

1.3 Role-Integrity Principle
Every screen, every button, every API call must be rendered and authorized based on Role + Property + Shift context. A manager at Property A must be invisible to Property B. A night-shift employee must not see day-shift payroll data. This is not just middleware — it is the DNA of every component.

1.4 Audit-First Design
Every state change in the system — price override, room reassignment, discount applied, complaint escalated — must generate an immutable audit log entry with: Actor ID, Role, Timestamp (UTC + local), Previous Value, New Value, IP Address, Device Fingerprint, and Session Token. This is non-negotiable for compliance (GDPR, PCI-DSS, ISO 27001).

1.5 Revenue Intelligence by Default
This system must not merely record transactions. It must predict, optimize, and alert. Every dashboard at every role level must surface actionable revenue intelligence — not vanity metrics.

📊 SECTION 6: ANALYTICS ENGINE SPECIFICATION

6.1 Key Performance Indicators (KPIs) — Defined

Every KPI displayed must be calculated correctly. Never approximate.

Occupancy Rate = (Occupied Rooms / Available Rooms) × 100
Available Rooms = Total Rooms - Out of Order Rooms

ADR (Average Daily Rate) = Total Room Revenue / Total Rooms Sold
Rooms Sold = Occupied rooms. Complimentary rooms excluded from revenue but included in occupancy.

RevPAR (Revenue Per Available Room) = ADR × Occupancy Rate
OR RevPAR = Total Room Revenue / Available Rooms
Both formulas yield the same result — verify in code.

TRevPAR (Total Revenue Per Available Room) = Total Property Revenue / Available Rooms
Includes F&B, SPA, Laundry, Other — not just rooms

GOPPAR (Gross Operating Profit Per Available Room) = Gross Operating Profit / Available Rooms

NPS (Net Promoter Score) = % Promoters (9-10) - % Detractors (0-6)

CPOR (Cost Per Occupied Room) = Total Operating Expenses / Occupied Rooms

Channel Contribution % = Revenue from Channel / Total Revenue × 100

🔒 SECTION 7: SECURITY ARCHITECTURE

7.1 Application Security

OWASP Top 10 mitigation — every item addressed:


Injection: Prisma ORM parameterized queries. Zero raw SQL with user input.
Broken Auth: JWT RS256 + Refresh token rotation + session blacklist in Redis.
Sensitive Data Exposure: AES-256 for guest PII at rest. TLS 1.3 in transit. PAN tokenization for payment data.
XML/XXE: Not applicable (JSON API). Validate all external XML (OTA channel feeds).
Broken Access Control: Row-Level Security in PostgreSQL. API middleware validates role + property ownership on every request.
Security Misconfiguration: Helm charts + Terraform with security groups. No default credentials. Secrets in AWS Secrets Manager only.
XSS: Content Security Policy headers. React JSX escapes by default. Sanitize all rich text inputs with DOMPurify.
Insecure Deserialization: Zod schema validation on all incoming payloads. No eval() or JSON.parse on untrusted data.
Vulnerable Dependencies: Snyk + Dependabot automated scanning. Weekly dependency audit in CI.
Insufficient Logging: Every API request logged with RequestID. Audit log for all state changes (see Section 4.9).


Additional Controls:


Rate limiting: 100 req/min per IP on public endpoints, 1000 req/min per authenticated user (Redis-backed via express-rate-limit)
CORS: Whitelist only known frontend domains
Helmet.js: Set all security headers (HSTS, X-Frame-Options, CSP, etc.)
SQL injection: Prisma prevents by design. Additional: pg-escape for any raw queries
File uploads: Type validation, size limit (10MB), virus scan via ClamAV before storage
PCI-DSS compliance: Never store raw card numbers. Use Razorpay/Stripe tokenization.


7.2 Data Privacy (GDPR / PDPB Compliance)


Guest PII encrypted at column level (name, email, phone, ID number)
Guest data deletion API (right to be forgotten) — anonymizes, does not hard-delete (preserve financial records)

9.2 Night Audit Automation

Night Audit runs at property's configured rollover time (default: 11:59 PM local time). This is the most critical automated process.

Night Audit Steps (automated, sequential, atomic transaction):


Post room charges to all in-house folios (room rate × nights)
Post meal plan charges (if MAP/AP package)
Advance reservations arriving tomorrow from tentative to confirmed
Mark no-shows (reservations with check-in date = today, status = confirmed, not checked in)
Apply cancellation charges for no-shows per policy
Roll business date to next day
Generate Night Audit report
Email report to GM and Owner
Backup snapshot of all financial data to audit-safe storage


If any step fails: Rollback entire transaction. Alert GM via push notification. Log failure with full context.
